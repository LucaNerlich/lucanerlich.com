# Touch UI Component Dialog Examples

The following chapters each present a Coral XML snippet which can be copied into any component's `_cq_dialog/.content.xml`.

A dialog is the form an author gets when they configure a component. Each widget is a Granite UI resource, and the `name` on that widget is the JCR property written on the component content node.

```text
ui.apps/.../components/teaser/
  .content.xml                    # cq:Component
  teaser.html
  _cq_dialog/.content.xml         # node name: cq:dialog
  _cq_design_dialog/.content.xml  # template policy
  _cq_editConfig.xml              # inline editing, drop targets
```

`_cq_dialog` keeps the colon out of the filename. FileVault turns the underscore into `cq:dialog`. Build new dialogs with Coral 3 resource types (`granite/ui/components/coral/foundation/...`). Coral 2 widgets live under `granite/ui/components/foundation` and still show up in older projects; the pathbrowser section below is the one you will recognise.

A value is stored only when `name` is relative to the component:

```xml
name="./title"
```

Without the `./` the POST lands on the wrong resource and the dialog looks like it does not save. The XML element name (`<title>`, `<heading>`, `<alert>`) only has to be unique among siblings. It is not the property name.

```text
/content/mysite/en/jcr:content/root/teaser
  title = "Spring collection"
  fileReference = "/content/dam/spring.jpg"
  links/            # composite multifield, name="./links"
    item0/  label, url
    item1/  label, url
```

For a first component, the [beginners guide dialog chapter](./beginners-guide/06-component-dialogs.md) walks through one dialog end to end. This page is the catalog you copy from after that. Widget contracts live in the [Granite UI server-side API](https://developer.adobe.com/experience-manager/reference-materials/6-5/granite-ui/api/jcr_root/libs/granite/ui/components/coral/foundation/server.html).

## TL;DR

- Start from the empty dialog template and evolve it.
- Use `fieldLabel` + `fieldDescription` consistently for author guidance.
- Prefer `composite` multifields and `@ChildResource` when you need structured data.
- Reach for `cq-dialog-dropdown-showhide` before writing a dialog clientlib.
- Set `uncheckedValue` on checkboxes, and `selected` on the default select option.
- Keep validation minimal and handle missing values in your Sling Model.

## Best Practices

1. If possible, extend an existing core component.
2. Version your components `<component>/<version>/<component>`.
3. Structure your fields into tabs where it makes sense
4. Do not overuse [multifields](#multifield)
5. Use as few fields as possible, but as many as necessary
6. Use Granite Alerts for important hints or notes
7. Use granite wells where fields could be visually grouped.
8. Add a component README.md file to help authors
9. Add clientLib files directly into the component folder if necessary
10. Don't overdo validation, handle missing fields gracefully in the model as well

## Common pitfalls

- Missing `name`, or a `name` without the `./` prefix. The field renders and the POST goes nowhere useful.
- A checkbox with no `uncheckedValue`. Clearing it deletes the property, so the model sees `null` instead of `false`.
- A select or radio with no `selected` item. The closed dialog shows the first option, and nothing is stored until the author changes it.
- Treating the multifield's own node name as the JCR name. For a composite multifield the stored node is the `name` on the inner `field` container.
- `min-items` / `max-items` with no validator. Those data attributes are inert until the [multifield validator](./components/dialog-validation.mdx#multifield-min--max-items) is registered.
- `required` on a field that show/hide can hide. The `hide` class does not turn validation off, so save stays blocked.
- A numberfield with no `@TypeHint`. The value is stored as a String.
- Renaming `name` after content exists, with no fallback in the Sling Model.
- Pasting `sling:hideChildren="[*]"` into a proxy dialog. That drops every inherited tab. See [Dialog Inheritance](#dialog-inheritance).
- Forgetting `fieldLabel`, which makes the dialog harder to scan and leaves the input unlabelled for assistive tech.
- A composite multifield where a fixed group of fields would do. A [fieldset](#fieldset-grouped-fields) is the smaller tool.
- A dialog clientlib on `cq.authoring.dialog`, so the script loads in every dialog. Prefer `extraClientlibs`.

## Empty Dialog / Starting Point

This is an empty dialog structure and components can be placed in tabs (you can add `n` tabs.)

![Dialog tabs](/images/aem/dialogfields/tabs.png)

```xml title="/components/mycomponent/_cq_dialog/.content.xml"
<?xml version="1.0" encoding="UTF-8"?>
<jcr:root xmlns:sling="http://sling.apache.org/jcr/sling/1.0" xmlns:granite="http://www.adobe.com/jcr/granite/1.0" xmlns:cq="http://www.day.com/jcr/cq/1.0" xmlns:jcr="http://www.jcp.org/jcr/1.0" xmlns:nt="http://www.jcp.org/jcr/nt/1.0"
          jcr:primaryType="nt:unstructured"
          jcr:title="MyTestComponent"
          sling:resourceType="cq/gui/components/authoring/dialog"
          helpPath="https://url-to-your-documentation.com">
    <content
            granite:class="cmp-mytestcmp__editor"
            jcr:primaryType="nt:unstructured"
            sling:resourceType="granite/ui/components/coral/foundation/container">
        <items jcr:primaryType="nt:unstructured">
            <tabs
                    jcr:primaryType="nt:unstructured"
                    sling:resourceType="granite/ui/components/coral/foundation/tabs"
                    maximized="{Boolean}true">
                <items jcr:primaryType="nt:unstructured">
                    <properties
                            jcr:primaryType="nt:unstructured"
                            jcr:title="Properties"
                            sling:resourceType="granite/ui/components/coral/foundation/container"
                            margin="{Boolean}true">
                        <items jcr:primaryType="nt:unstructured">
                            <columns
                                    jcr:primaryType="nt:unstructured"
                                    sling:resourceType="granite/ui/components/coral/foundation/fixedcolumns"
                                    margin="{Boolean}true">
                                <items jcr:primaryType="nt:unstructured">
                                    <column
                                            jcr:primaryType="nt:unstructured"
                                            sling:resourceType="granite/ui/components/coral/foundation/container">
                                        <items jcr:primaryType="nt:unstructured">
                                        <!--  Place your components / dialog fields here  -->
                                        </items>
                                    </column>
                                </items>
                            </columns>
                        </items>
                    </properties>
                    <layout
                            jcr:primaryType="nt:unstructured"
                            jcr:title="Layout"
                            sling:resourceType="granite/ui/components/coral/foundation/container"
                            margin="{Boolean}true">
                        <items jcr:primaryType="nt:unstructured">
                            <columns
                                    jcr:primaryType="nt:unstructured"
                                    sling:resourceType="granite/ui/components/coral/foundation/fixedcolumns"
                                    margin="{Boolean}true">
                                <items jcr:primaryType="nt:unstructured">
                                    <column
                                            jcr:primaryType="nt:unstructured"
                                            sling:resourceType="granite/ui/components/coral/foundation/container">
                                        <items jcr:primaryType="nt:unstructured">
                                        <!--  Place your components / dialog fields here  -->
                                        </items>
                                    </column>
                                </items>
                            </columns>
                        </items>
                    </layout>
                </items>
            </tabs>
        </items>
    </content>
</jcr:root>
```

![Empty dialog](/images/aem/dialogfields/empty.png)

Authors see one tab per child of `tabs/items`. Put fields in that tab's column `items`. `jcr:title` is the tab label. `margin="{Boolean}true"` is the padding; without it the fields sit on the dialog chrome. `maximized="{Boolean}true"` lets the tab body fill the dialog.

`granite:class` and `granite:id` land on the widget root, which is how dialog CSS and show/hide scripts find a field. `required="{Boolean}true"` on a form field marks it required.

<div class="alert alert-info" role="alert">
    The XML element name can be anything, as long as it is unique among its siblings.
    The Alert snippet does not have to be named <code>alert</code>. The <code>name</code> attribute is what gets stored.
</div>

## Simple Data Fields

### Textfield

[Documentation](https://developer.adobe.com/experience-manager/reference-materials/6-5/granite-ui/api/jcr_root/libs/granite/ui/components/coral/foundation/form/textfield/index.html)

```xml
<textfield
   jcr:primaryType="nt:unstructured"
   sling:resourceType="granite/ui/components/coral/foundation/form/textfield"
   fieldDescription="The button label"
   fieldLabel="Button Label"
   name="./label"
   emptyText="Learn more"/>
```

`emptyText` is the placeholder and is not saved. `value` is submitted with the dialog, so it becomes real content on the first save even when the author never touches the field. Put fallbacks in the Sling Model when they should stay out of the JCR. See [Persisted values and defaults](#persisted-values-and-defaults).


### Numberfield

[Documentation](https://developer.adobe.com/experience-manager/reference-materials/6-5/granite-ui/api/jcr_root/libs/granite/ui/components/coral/foundation/form/numberfield/index.html)

You can define the min, max value and the increments, in which the input can be set.

```xml
<numberfield
    jcr:primaryType="nt:unstructured"
    sling:resourceType="granite/ui/components/coral/foundation/form/numberfield"
    fieldLabel="Choose a number value"
    name="./numbervalue"
    min="{Long}1"
    max="{Long}10"
    step="{Double}1"/>
```

The widget posts a string, so the JCR property is `"1"` unless the submit also carries a Sling type hint. Add a hidden sibling when the property should be a `Long` (or `Double` for decimals):

```xml
<numberTypeHint
    jcr:primaryType="nt:unstructured"
    sling:resourceType="granite/ui/components/coral/foundation/form/hidden"
    name="./numbervalue@TypeHint"
    value="Long"/>
```

A Sling Model `long` converts the string and hides the mismatch until a query or a script compares types.

![Numberfield](/images/aem/dialogfields/numberfield.png)

### Pathfield (Pathbrowser)

[Documentation](https://developer.adobe.com/experience-manager/reference-materials/6-5/granite-ui/api/jcr_root/libs/granite/ui/components/coral/foundation/form/pathfield/index.html)

```xml
<pathfield
   jcr:primaryType="nt:unstructured"
   sling:resourceType="granite/ui/components/coral/foundation/form/pathfield"
   fieldLabel="Select path"
   rootPath="/content"
   name="./path"/>
```

`rootPath` is case-sensitive. `rootpath` is ignored and the picker opens at `/`.

`filter` limits the picker:

| `filter` | Picker shows |
|----------|----------------|
| `hierarchyNotFile` | Pages and folders, not assets |
| `nosystem` | Hides `/apps`, `/libs`, and other system paths |
| omitted | Pages and assets |

An asset picker uses `rootPath="/content/dam"` and no `filter`. `hierarchyNotFile` on a DAM root hides the assets you wanted the author to pick.

![Pathfield](/images/aem/dialogfields/pathfield.png)

#### Pathfield picker options

```xml
<pathfield
   jcr:primaryType="nt:unstructured"
   sling:resourceType="granite/ui/components/coral/foundation/form/pathfield"
   fieldLabel="Select asset"
   forceSelection="{Boolean}true"
   rootPath="/content/dam"
   pickerSrc="/mnt/overlay/granite/ui/content/coral/foundation/form/pathfield/picker.html"
   name="./assetPath"/>
```

For an implementation of a dynamic rootPath, see [Custom Dialog Widgets - Dynamic PathField](./ui/custom-dialog-widgets.md#dynamic-pathfield-root-path).

#### Pathbrowser

In legacy AEM 6.5 codebases you might still encounter the older Coral 2 `pathbrowser` component. Prefer the Coral 3 `pathfield` above for new dialogs, especially for AEM as a Cloud Service projects.

### Asset Upload

[Documentation](https://developer.adobe.com/experience-manager/reference-materials/6-5/granite-ui/api/jcr_root/libs/granite/ui/components/coral/foundation/form/fileupload/index.html)

```xml
<file
    jcr:primaryType="nt:unstructured"
    sling:resourceType="cq/gui/components/authoring/dialog/fileupload"
    class="cq-droptarget"
    fileNameParameter="./fileName"
    fileReferenceParameter="./fileReference"
    mimeTypes="[image/gif,image/jpeg,image/png,image/tiff,image/svg+xml]"
    fieldLabel="Image"
    name="./file"/>
```

`fileReferenceParameter` is the DAM path written when the author picks an existing asset (`./fileReference`). `name="./file"` is the binary child used when they upload from disk. Drag-and-drop from the asset finder also needs a matching [drop target](#drop-target-for-assets) on `cq:editConfig`. Set `allowUpload="{Boolean}false"` when the asset must already live in the DAM.

### Checkbox

[Documentation](https://developer.adobe.com/experience-manager/reference-materials/6-5/granite-ui/api/jcr_root/libs/granite/ui/components/coral/foundation/form/checkbox/index.html)

```xml
<checkbox
    jcr:primaryType="nt:unstructured"
    sling:resourceType="granite/ui/components/coral/foundation/form/checkbox"
    checked="{Boolean}true"
    name="./altValueFromPageImage"
    text="Inherit alternative text from page"
    uncheckedValue="{Boolean}false"
    value="{Boolean}true"/>
```

`text` is the checkbox caption. A `fieldLabel` on the same widget draws a second caption above it.

`value` is written when the box is checked. `uncheckedValue` is written when it is cleared. Omit `uncheckedValue` and clearing the box deletes the property: a primitive `boolean` in the Sling Model reads `false`, a `Boolean` reads `null`. `checked` applies only while the property is missing; once the author has saved, the stored value wins.

![Checkbox](/images/aem/dialogfields/checkbox.png)

### Checkbox group

```xml
<checkboxGroup
    jcr:primaryType="nt:unstructured"
    sling:resourceType="granite/ui/components/coral/foundation/form/checkboxgroup"
    fieldLabel="Options"
    name="./options">
    <items jcr:primaryType="nt:unstructured">
        <optA text="Option A" value="a" jcr:primaryType="nt:unstructured"/>
        <optB text="Option B" value="b" jcr:primaryType="nt:unstructured"/>
    </items>
</checkboxGroup>
```

Checked options are stored as a `String[]` on `./options`. Read it with `@ValueMapValue private String[] options`. There is no `uncheckedValue` here: clearing every box removes the property.

### Switch

[Documentation](https://developer.adobe.com/experience-manager/reference-materials/6-5/granite-ui/api/jcr_root/libs/granite/ui/components/coral/foundation/form/switch/index.html)

```xml
<switch
   jcr:primaryType="nt:unstructured"
   sling:resourceType="granite/ui/components/coral/foundation/form/switch"
   checked="{Boolean}true"
   name="./switchValue"
   fieldLabel="Toggle Me"
   uncheckedValue="{Boolean}false"
   value="{Boolean}true"/>
```

A switch persists the same way as a checkbox: `value` when on, `uncheckedValue` when off, property deleted when `uncheckedValue` is missing. `onText` and `offText` replace the default labels.

![Switch](/images/aem/dialogfields/switch.png)

#### Switch with labels

```xml
<switch
   jcr:primaryType="nt:unstructured"
   sling:resourceType="granite/ui/components/coral/foundation/form/switch"
   fieldLabel="Enable feature"
   onText="On"
   offText="Off"
   name="./featureEnabled"
   uncheckedValue="{Boolean}false"
   value="{Boolean}true"/>
```

### Datepicker

[Documentation](https://developer.adobe.com/experience-manager/reference-materials/6-5/granite-ui/api/jcr_root/libs/granite/ui/components/coral/foundation/form/datepicker/index.html)

```xml
<datepicker
   jcr:primaryType="nt:unstructured"
   sling:resourceType="granite/ui/components/coral/foundation/form/datepicker"
   displayedFormat="MM-DD-YYYY HH:mm"
   fieldLabel="datepicker"
   name="./datepicker"
   type="datetime"
   typeHint="Date"/>
```

`displayedFormat` uses [Moment](https://momentjs.com/docs/#/displaying/format/) tokens, not `SimpleDateFormat`. `DD` is the day of the month and `dd` is the day of the week, so a Java-style `dd-MM-yyyy` renders the weekday. `YYYY-MM-DD` is the usual date-only format.

`type` is `date`, `time`, or `datetime`. `typeHint="Date"` stores a JCR Date, which a `Calendar` injection can read. Without the hint the value is an ISO string and the `Calendar` comes back null.

![Datepicker](/images/aem/dialogfields/datepicker.png)

#### Datepicker constraints

```xml
<datepicker
   jcr:primaryType="nt:unstructured"
   sling:resourceType="granite/ui/components/coral/foundation/form/datepicker"
   fieldLabel="Publish date"
   minDate="2024-01-01"
   maxDate="2030-12-31"
   displayedFormat="YYYY-MM-DD"
   name="./publishDate"/>
```

## Complex Data Fields

### Conditional fields (show/hide)

Use a render condition when you need server-side control (for example, permissions or site-level logic).
A render condition decides whether a field is even *rendered* into the dialog HTML - the author
cannot reveal it from the client. See the dedicated [Render Conditions](./ui/render-conditions.mdx)
page for the full pattern (custom `rendercondition` resource type + server-side logic), and Adobe's
[Granite UI render condition reference](https://developer.adobe.com/experience-manager/reference-materials/6-5/granite-ui/api/jcr_root/libs/granite/ui/components/coral/foundation/renderconditions/index.html).

```xml
<advancedSettings
    jcr:primaryType="nt:unstructured"
    sling:resourceType="granite/ui/components/coral/foundation/container">
    <granite:rendercondition
        jcr:primaryType="nt:unstructured"
        sling:resourceType="com.myproject/renderconditions/isAdmin"/>
    <items jcr:primaryType="nt:unstructured">
        <!-- advanced fields -->
    </items>
</advancedSettings>
```

For client-side toggles (show/hide based on a checkbox or select), prefer dialog JS in a small clientlib scoped to dialog usage.

### Native showhide with cq-dialog-dropdown-showhide

The dialog editor already loads `cq.authoring.dialog`, and that clientlib contains Adobe's show/hide script. You do not register anything. A select (or checkbox) with the class below toggles every element that carries the matching target class and `showhidetargetvalue`.

**Dropdown-controlled target**

```xml
<linkType
    jcr:primaryType="nt:unstructured"
    sling:resourceType="granite/ui/components/coral/foundation/form/select"
    fieldLabel="Link Type"
    name="./linkType"
    granite:class="cq-dialog-dropdown-showhide">
    <granite:data
        jcr:primaryType="nt:unstructured"
        cq-dialog-dropdown-showhide-target=".cmp-link-type-target"/>
    <items jcr:primaryType="nt:unstructured">
        <internal jcr:primaryType="nt:unstructured" text="Internal" value="internal"/>
        <external jcr:primaryType="nt:unstructured" text="External" value="external"/>
        <email    jcr:primaryType="nt:unstructured" text="Email"    value="email"/>
    </items>
</linkType>

<internalPath
    jcr:primaryType="nt:unstructured"
    sling:resourceType="granite/ui/components/coral/foundation/form/pathfield"
    fieldLabel="Internal Path"

    <granite:data
        jcr:primaryType="nt:unstructured"
        showhidetargetvalue="email"/>
</emailAddress>
```

How Adobe's script resolves it:

1. The select fires a `change` event; the script reads `cq-dialog-dropdown-showhide-target`.
2. It queries the document for every element matching that selector (e.g. `.cmp-link-type-target`).
3. For each target, it reads the target's `showhidetargetvalue` and compares to the current select value.
4. Matching targets lose the `hide` class; the others gain it. On `dialog-ready` the script runs against the saved value, so a field can start with `hide` and still be visible when the stored value matches.

:::warning[A hidden required field still blocks save]
The script toggles `hide`. It does not disable Foundation validation. A target with `required="{Boolean}true"` fails the dialog while it is hidden. Leave `required` off fields that can be hidden, or register a validator that skips `.hide` ancestors. See [Dialog Validation](./components/dialog-validation.mdx).
:::

**3) Toggle the row the author is editing**

`granite:class` lands on the field wrapper for some widgets and on `coral-select` for others. Resolve the select either way, then scope the target lookup to `coral-multifield-item`. New rows are inserted after `dialog-ready`, so a `MutationObserver` on the multifield has to run init again. Toggling `display` (instead of adding and removing nodes) keeps a row that was just added in the right state.

```js title="ui.apps/.../clientlibs/clientlib-dialog/js/dialog-visibility.js"
(function (document, $) {
    "use strict";

    var SOURCE = ".linkType-showhide-source";
    var TARGET = ".linkType-showhide-target";

    function findSelect(source) {
        if (source.tagName === "CORAL-SELECT") {
            return source;
        }
        return source.querySelector("coral-select");
    }

    function toggle(select) {
        var row = $(select).closest("coral-multifield-item");
        var scope = row.length ? row : $(document);
        var showEmail = select.value === "email";

        scope.find(TARGET).each(function () {
            var wrapper = $(this).closest("div.coral-Form-fieldwrapper");
            (wrapper.length ? wrapper : $(this)).toggle(showEmail);
        });
    }

    function init(root) {
        $(root).find(SOURCE).each(function () {
            var select = findSelect(this);
            if (!select || select.dataset.linktypeInitialized) {
                return;
            }
            select.dataset.linktypeInitialized = "true";
            toggle(select);
            $(select).on("change", function () {
                toggle(select);
            });
        });
    }

    $(document).on("dialog-ready", function () {
        init(document);

        document.querySelectorAll("coral-multifield").forEach(function (multifield) {
            new MutationObserver(function () {
                init(multifield);
            }).observe(multifield, { childList: true });
        });
    });
})(document, Granite.$);
```

#### The datasource servlet

The `datasource` `sling:resourceType` points at a servlet that builds the option list at dialog-render
time. The servlet sets a `DataSource` request attribute whose items are resources of type
`nt:unstructured` carrying `value` and `text` properties - exactly what the select expects.

```java title="core/.../servlets/CategoryDatasourceServlet.java"
import com.adobe.granite.ui.components.ds.DataSource;
import com.adobe.granite.ui.components.ds.SimpleDataSource;
import com.adobe.granite.ui.components.ds.ValueMapResource;
import org.apache.sling.api.SlingHttpServletRequest;
import org.apache.sling.api.SlingHttpServletResponse;
import org.apache.sling.api.resource.ResourceMetadata;
import org.apache.sling.api.resource.ResourceResolver;
import org.apache.sling.api.resource.ValueMap;
import org.apache.sling.api.wrappers.ValueMapDecorator;
import org.apache.sling.servlets.annotations.SlingServletResourceTypes;
import org.osgi.service.component.annotations.Component;

import javax.servlet.Servlet;
import java.util.ArrayList;
import java.util.Iterator;
import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

@Component(service = Servlet.class)
@SlingServletResourceTypes(
    resourceTypes = "myproject/datasource/categories",
    methods = "GET"
)
public class CategoryDatasourceServlet extends org.apache.sling.api.servlets.SlingSafeMethodsServlet {

    @Override
    protected void doGet(SlingHttpServletRequest request, SlingHttpServletResponse response) {
        ResourceResolver resolver = request.getResourceResolver();

        // Source your options however you like: a config, a query, a service, a taxonomy...
        Map<String, String> options = new LinkedHashMap<>();
        options.put("news", "News");
        options.put("blog", "Blog");
        options.put("press", "Press Release");

        List<org.apache.sling.api.resource.Resource> items = new ArrayList<>();
        for (Map.Entry<String, String> entry : options.entrySet()) {
            ValueMap vm = new ValueMapDecorator(new java.util.HashMap<>());
            vm.put("value", entry.getKey());
            vm.put("text", entry.getValue());
            items.add(new ValueMapResource(resolver, new ResourceMetadata(), "nt:unstructured", vm));
        }

        Iterator<org.apache.sling.api.resource.Resource> it = items.iterator();
        DataSource ds = new SimpleDataSource(it);
        request.setAttribute(DataSource.class.getName(), ds);
    }
}
```

:::tip[The saved value selects itself]
The select compares each option's `value` with the property already stored on the component. A datasource item with that `value` is selected on open, the same as a static item. Set `selected="{Boolean}true"` only for the default, when the property is still missing.
:::

### Multifield

[Documentation](https://developer.adobe.com/experience-manager/reference-materials/6-5/granite-ui/api/jcr_root/libs/granite/ui/components/coral/foundation/form/multifield/index.html)

A multifield lets an author add *n* copies of a field or a field group. There are two storage shapes, and they are not interchangeable.

**Flat** (no `composite`) stores one multi-value property. The `name` on the inner field is that property:

```xml
<keywords
    jcr:primaryType="nt:unstructured"
    sling:resourceType="granite/ui/components/coral/foundation/form/multifield"
    fieldLabel="Keywords">
    <field
        jcr:primaryType="nt:unstructured"
        sling:resourceType="granite/ui/components/coral/foundation/form/textfield"
        name="./keywords"/>
</keywords>
```

```text
teaser
  keywords = ["spring", "lookbook"]    String[]
```

Read it with `@ValueMapValue private String[] keywords`.

**Composite** (`composite="{Boolean}true"`) stores ordered child nodes. The JCR name is the `name` on the inner `field` container, not the multifield element's own node name. Inner fields use their own `./` names, relative to each item:

```text
teaser
  links/                 # name="./links" on the field container
    item0/  text = "..."
    item1/  text = "..."
```

`@ChildResource` injects that list. The child model adapts from `Resource`, and the list follows JCR child order. Sort by that order. Sorting the node names as strings puts `item10` before `item2`.

```java
import java.util.Collections;
import java.util.List;

import org.apache.sling.api.SlingHttpServletRequest;
import org.apache.sling.api.resource.Resource;
import org.apache.sling.models.annotations.Model;
import org.apache.sling.models.annotations.injectorspecific.ChildResource;
import org.apache.sling.models.annotations.injectorspecific.ValueMapValue;

@Model(adaptables = SlingHttpServletRequest.class)
public class LinkList {

    @ChildResource
    private List<Link> links;

    public List<Link> getLinks() {
        return links != null ? links : Collections.emptyList();
    }

    @Model(adaptables = Resource.class)
    public static class Link {
        @ValueMapValue
        private String text;

        public String getText() {
            return text;
        }
    }
}
```

The full pattern, including a multifield of nested models, is on the [`@ChildResource`](./components/annotations/child-resource.mdx) page.

### FieldSet (grouped fields)

[Documentation](https://developer.adobe.com/experience-manager/reference-materials/6-5/granite-ui/api/jcr_root/libs/granite/ui/components/coral/foundation/form/fieldset/index.html)

A `fieldset` groups related fields under a single legend, and -- usefully -- prefixes every nested
field's property name so the values land in a subnode of the component. This is the cleanest way
to persist "a logical sub-object" (e.g. social links, SEO metadata) without reaching for a
multifield.

```xml
<social
    jcr:primaryType="nt:unstructured"
    sling:resourceType="granite/ui/components/coral/foundation/form/fieldset"
    jcr:title="Social Links"
    name="./social">
    <items jcr:primaryType="nt:unstructured">
        <twitter
            jcr:primaryType="nt:unstructured"
            sling:resourceType="granite/ui/components/coral/foundation/form/textfield"
            fieldLabel="Twitter / X"
            name="./twitter"/>
        <linkedin
            jcr:primaryType="nt:unstructured"
            sling:resourceType="granite/ui/components/coral/foundation/form/textfield"
            fieldLabel="LinkedIn"
            name="./linkedin"/>
    </items>
</social>
```

The above persists to:

```text
myComponent
  └─ social/
       ├─ twitter = "..."
       └─ linkedin = "..."
```

Read it in a Sling Model with `@ChildResource`:

```java
@ChildResource
private Resource social;

public String getTwitter() {
    return social != null ? social.getValueMap().get("twitter", String.class) : null;
}
```

:::tip[Fieldset vs Well vs Multifield]
- **Well** - visual grouping only. No name prefix, no subnode.
- **Fieldset** - visual grouping *and* persistence into a subnode (`name="./social"`).
- **Multifield** - use only when authors can add *n* repeating items. A fieldset is almost always
  the right choice for a fixed group of fields.
:::

### Tags field

See also the [Tags and Taxonomies](./content/tags-taxonomies.md) deep dive.

```xml
<tags
    jcr:primaryType="nt:unstructured"
    sling:resourceType="cq/gui/components/coral/common/form/tagfield"
    fieldLabel="Tags"
    name="./cq:tags"
    multiple="{Boolean}true"
    rootPath="/content/cq:tags/myproject"/>
```

- `name="./cq:tags"` is the conventional property name - Sling and AEM search already understand
  it, and `com.day.cq.tagging.TagManager` reads it by default.
- `rootPath` restricts the picker to a specific taxonomy branch, which keeps authors from tagging
  with marketing tags intended for other projects. Omit it only when the component is truly
  cross-project.
- `multiple="{Boolean}true"` persists a `String[]` - even for a single tag, this is usually what
  you want, since it matches the AEM default.

Reading tags in a Sling Model - never concatenate paths, let `TagManager` resolve them so admin
UI paths are treated correctly:

```java
import com.day.cq.tagging.Tag;
import com.day.cq.tagging.TagManager;
import org.apache.sling.api.SlingHttpServletRequest;
import org.apache.sling.models.annotations.injectorspecific.Self;
import org.apache.sling.models.annotations.injectorspecific.ValueMapValue;

import java.util.Arrays;
import java.util.Collections;
import java.util.List;
import java.util.Objects;
import java.util.stream.Collectors;

@ValueMapValue(name = "cq:tags")
private String[] tagIds;

@Self
private SlingHttpServletRequest request;

public List<Tag> getTags() {
    if (tagIds == null || tagIds.length == 0) {
        return Collections.emptyList();
    }
    TagManager tagManager = request.getResourceResolver().adaptTo(TagManager.class);
    if (tagManager == null) {
        return Collections.emptyList();
    }
    return Arrays.stream(tagIds)
            .map(tagManager::resolve)
            .filter(Objects::nonNull)
            .collect(Collectors.toList());
}
```

See [Tags and Taxonomies](./content/tags-taxonomies.md) for the full model, including reading
localized tag titles and filtering by namespace.

```xml
            jcr:primaryType="nt:unstructured"
            sling:resourceType="granite/ui/components/coral/foundation/form/pathfield"
            fieldLabel="URL or path"
            fieldDescription="Internal paths or full URLs (https://...)"
            name="./url"/>
        <target
            jcr:primaryType="nt:unstructured"
            sling:resourceType="granite/ui/components/coral/foundation/form/select"
            fieldLabel="Open in"
            name="./target">
            <items jcr:primaryType="nt:unstructured">
                <self  jcr:primaryType="nt:unstructured" text="Same tab"  value="_self" selected="{Boolean}true"/>
                <blank jcr:primaryType="nt:unstructured" text="New tab"   value="_blank"/>
            </items>
        </target>
    </items>
</link>
```

Sling Model reading the subnode as a structured object - and adding `rel` for `_blank` links:

```java
@Model(adaptables = Resource.class)
public class LinkModel {

    @ValueMapValue
    @Default(values = "")
    private String label;

    @ValueMapValue
    @Default(values = "")
    private String url;

    @ValueMapValue
    @Default(values = "_self")
    private String target;

    public String getRel() {
        // Only _blank needs noopener/noreferrer to prevent window.opener hijacking.
        return "_blank".equals(target) ? "noopener noreferrer" : null;
    }

    // label, url, target getters...
}
```

Adapt in the parent model with `@ChildResource`:

```java
@ChildResource
private LinkModel link;
```

### Content Fragment picker

`dam/cfm/components/cfpicker` is the Content Fragment picker (AEM 6.5 and Cloud Service). The attributes below are the ones on the Core Components Content Fragment dialog. A plain pathfield with `filter="hierarchyNotFile"` cannot select a fragment: that filter hides assets, and a content fragment is a `dam:Asset`.

```xml
<contentFragment
    jcr:primaryType="nt:unstructured"
    sling:resourceType="dam/cfm/components/cfpicker"
    fieldLabel="Content Fragment"
    fieldDescription="Path to the Content Fragment to display."
    emptyText="Enter or select Content Fragment"
    pickerTitle="Select Content Fragment"
    rootPath="/content/dam"
    name="./fragmentPath"/>
```

`rootPath` limits the browse root. The picker has no model filter of its own; restricting to one Content Fragment Model means a project-specific picker or a datasource. Read `fragmentPath` with `@ValueMapValue` and resolve the asset through the Content Fragment API.

### Experience Fragment picker

`cq/experience-fragments/editor/components/xffield` is the variation picker. ## Dialog Inheritance

### Extending a parent dialog with sling:resourceSuperType

When the component sets `sling:resourceSuperType`, the editor loads the dialog through Sling Resource Merger (`/mnt/override`). The child `cq:dialog` is merged onto the parent `cq:dialog`. Same node names merge, properties on the child win, and new nodes are added.

The node names along the path have to match the parent. A standard dialog keeps `content/items/tabs/items`. Rename `tabs` and the merger adds a second tab list instead of a tab.

The component property is what the merger follows. A `sling:resourceSuperType` on the dialog is the other case: point it at a dialog from a component this one does not extend, for example `core/wcm/components/text/v2/text/cq:dialog`.

`sling:orderBefore` names the sibling node that should come after yours. The value is the node name, not the `jcr:title`. Read it off the parent dialog in CRXDE.

```xml title="components/mytext/_cq_dialog/.content.xml"
<?xml version="1.0" encoding="UTF-8"?>
<jcr:root xmlns:sling="http://sling.apache.org/jcr/sling/1.0"
          xmlns:jcr="http://www.jcp.org/jcr/1.0"
          xmlns:nt="http://www.jcp.org/jcr/nt/1.0"
          jcr:primaryType="nt:unstructured"
          jcr:title="My Text"
          sling:resourceType="cq/gui/components/authoring/dialog">
    <content jcr:primaryType="nt:unstructured"
             sling:resourceType="granite/ui/components/coral/foundation/container">
        <items jcr:primaryType="nt:unstructured">
            <tabs jcr:primaryType="nt:unstructured"
                  sling:resourceType="granite/ui/components/coral/foundation/tabs"
                  maximized="{Boolean}true">
                <items jcr:primaryType="nt:unstructured">
                    <!-- New tab added to the inherited dialog -->
                    <analytics
                        jcr:primaryType="nt:unstructured"
                        jcr:title="Analytics"
                        sling:orderBefore="PARENT_TAB_NODE_NAME"
                        sling:resourceType="granite/ui/components/coral/foundation/container"
                        margin="{Boolean}true">
                        <items jcr:primaryType="nt:unstructured">
                            <trackingId
                                jcr:primaryType="nt:unstructured"
                                sling:resourceType="granite/ui/components/coral/foundation/form/textfield"
                                fieldLabel="Tracking ID"
                                name="./trackingId"/>
                        </items>
                    </analytics>
                </items>
            </tabs>
        </items>
    </content>
</jcr:root>
```

The component's `.content.xml` must reference the parent:

```xml title="components/mytext/.content.xml"
<jcr:root xmlns:jcr="http://www.jcp.org/jcr/1.0"
          xmlns:cq="http://www.day.com/jcr/cq/1.0"
          xmlns:sling="http://sling.apache.org/jcr/sling/1.0"
          jcr:primaryType="cq:Component"
          jcr:title="My Text"
          sling:resourceSuperType="core/wcm/components/text/v2/text"
          componentGroup="My Project"/>
```

Replace `PARENT_TAB_NODE_NAME` with a real sibling, or drop `sling:orderBefore` and the tab is appended.

### Hiding inherited tabs or fields with sling:hideChildren

`sling:hideChildren` is a merger property. It has to sit on the node whose children you want to drop, at the same path the parent uses. On `content/items/tabs/items` it drops tabs. On a column's `items` it drops fields. The names are node names.

```xml
<!-- Hide specific tabs by name -->
<items jcr:primaryType="nt:unstructured"
       sling:hideChildren="[layoutTab,stylesTab]">
    <!-- your additional tabs here -->
</items>
```

`[*]` drops every inherited child of that node, then your own children are added back:

```xml
<items jcr:primaryType="nt:unstructured"
       sling:hideChildren="[*]">
    <!-- only your own tabs will show -->
</items>
```

On a dialog that has no super type, `[*]` does nothing. On a proxy it wipes the inherited dialog. Keep it out of the [full example](#full-xml-example) below.

### Hiding a single field with granite:hide

Two properties hide one node. You only need the node name, at the same path as the parent field. Copying the rest of the field is unnecessary.

```xml
<unwantedField
    jcr:primaryType="nt:unstructured"
    granite:hide="{Boolean}true"/>
```

`granite:hide` leaves the node in the merged tree and tells Granite not to render it, so a further override can show it again. `sling:hideResource="{Boolean}true"` removes the node during the merge.

```xml
<unwantedField
    jcr:primaryType="nt:unstructured"
    sling:hideResource="{Boolean}true"/>
```

## cq editConfig - inline editing, listeners, drop targets

`_cq_editConfig.xml` (file system form) or the `cq:editConfig` node sits next to `_cq_dialog` and
controls how the component behaves in edit mode **before** the dialog opens: which inline editors
are allowed, what gets dropped onto the component, and which client-side events should re-render
the component after a save.

```text title="Component structure"
components/mycomponent/
  _cq_dialog/.content.xml         # dialog that opens on "configure"
  _cq_editConfig.xml              # inline editing + drop targets
  mycomponent.html
```

### Drop target for assets

Lets authors drag an image from the asset finder straight onto the component.

```xml title="_cq_editConfig.xml"
<?xml version="1.0" encoding="UTF-8"?>
<jcr:root xmlns:cq="http://www.day.com/jcr/cq/1.0"
          xmlns:jcr="http://www.jcp.org/jcr/1.0"
          xmlns:nt="http://www.jcp.org/jcr/nt/1.0"
          xmlns:sling="http://sling.apache.org/jcr/sling/1.0"
          jcr:primaryType="cq:EditConfig">
    <cq:dropTargets jcr:primaryType="nt:unstructured">
        <image
            jcr:primaryType="cq:DropTargetConfig"
            accept="[image/.*]"
            groups="[media]"
            propertyName="./fileReference">
            <parameters
                jcr:primaryType="nt:unstructured"
                sling:resourceType="myproject/components/mycomponent"/>
        </image>
    </cq:dropTargets>
</jcr:root>
```

The `propertyName` is where the path of the dragged asset is stored on the component's resource.
Mark the component HTML with `cq-droptarget` (or the clientlib-generated class) so the drop zone is
visible in edit mode.

### Inline editor (edit text without opening the dialog)

```xml
<cq:editConfig jcr:primaryType="cq:EditConfig">
    <cq:inplaceEditing
        jcr:primaryType="cq:InplaceEditingConfig"
        active="{Boolean}true"
        configPath="/apps/myproject/components/mycomponent/cq:editConfig/inplaceEditing"
        editorType="text">
        <config
            jcr:primaryType="nt:unstructured"
            editElementQuery=".cmp-mycomponent__title"
            propertyName="./title"
            textPropertyName="./title"/>
    </cq:inplaceEditing>
</cq:editConfig>
```

- `editorType="text"` - plain textfield inline editor.
- `editorType="plaintext"` - same, but strips HTML on save.
- `editorType="title"` - classic title editor (single line, pressing Enter saves).

For Rich Text inline editing, set `editorType="text"` and add the full `rtePlugins` config similar
to the dialog RTE widget - see [Rich Text Editor (RTE)](#rich-text-editor-rte) for the complete
plugin/toolbar structure.

### Listeners (refresh behaviour after save)

By default, AEM refreshes only the edited component. If a component's HTML depends on siblings
(e.g. a carousel that re-renders when a slide changes), broaden the refresh:

```xml
<cq:listeners
    jcr:primaryType="cq:EditListenersConfig"
    afteredit="REFRESH_PAGE"
    afterinsert="REFRESH_PAGE"
    afterdelete="REFRESH_PAGE"
    afterchildinsert="REFRESH_SELF"/>
```

| Value | Effect |
|-------|--------|
| `REFRESH_SELF` (default) | Re-render only this component |
| `REFRESH_PARENT` | Re-render the enclosing container |
| `REFRESH_PAGE` | Reload the whole page |
| Custom JS function name | Called with the edit event - use for targeted DOM updates |

:::warning[`REFRESH_PAGE` is a sledgehammer]
Every change forces a full page reload, which is slow and loses any unsaved edits in other
components. Reach for `REFRESH_SELF` or `REFRESH_PARENT` first; only escalate to `REFRESH_PAGE`
when siblings genuinely depend on each other.
:::

### Disabling default actions

Remove the "Copy" or "Delete" buttons from the component toolbar:

```xml
<cq:editConfig
    jcr:primaryType="cq:EditConfig"
    cq:actions="[edit,insert]"/>
```

Omitting `copymove` and `delete` hides those toolbar buttons. `cq:actions` replaces the whole list, including `editannotate` on versions that show annotations. The common set is `[edit,copymove,delete,insert]`. Add back any action you still want.

Reading policy values in a Sling Model:

```java
import com.day.cq.wcm.api.policies.ContentPolicy;
import com.day.cq.wcm.api.policies.ContentPolicyManager;

@Model(adaptables = SlingHttpServletRequest.class)
public class MyComponentModel {

    @SlingObject
    private Resource resource;

    public String getDefaultHeadingLevel() {
        ContentPolicyManager policyManager = resource.getResourceResolver()
            .adaptTo(ContentPolicyManager.class);
        if (policyManager != null) {
            ContentPolicy policy = policyManager.getPolicy(resource);
            if (policy != null) {
                return policy.getProperties().get("headingLevel", "h2");
            }
        }
        return "h2";
    }
}
```

## Persisted values and defaults

- Use `./propertyName` to persist values on the component node.
- When changing field names, add migration logic or fallback in your model.
- Prefer handling defaults in Sling Models rather than relying solely on dialog defaults.

```java
@ValueMapValue
private String variant;
```

## Field naming conventions

- Always include the `./` prefix to store values on the current component node.
- Use consistent prefixes for related fields (for example, `ctaText`, `ctaLink`).
- Avoid renaming existing fields unless you migrate content.

## Rich Text Editor (RTE)

The Rich Text Editor (`cq/gui/components/authoring/dialog/richtext`) is the most configurable field in
the dialog framework. It is driven by **plugins** (each plugin contributes toolbar buttons and
behaviours) and a **toolbar** definition that decides which of those buttons are shown. The official
references are Adobe's
[Configuring the Rich Text Editor](https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/implementing/configuring-and-extending/rich-text-editor)
guide and the
[Configure the RTE plug-ins (Experience League)](https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/implementing/configuring-and-extending/configure-rich-text-editor-plug-ins).

### Minimal inline RTE

```xml
<text
    jcr:primaryType="nt:unstructured"
    sling:resourceType="cq/gui/components/authoring/dialog/richtext"
    name="./text"
    useFixedInlineToolbar="{Boolean}true">
    <uiSettings jcr:primaryType="nt:unstructured">
        <cui jcr:primaryType="nt:unstructured">
            <inline
                jcr:primaryType="nt:unstructured"
                toolbar="[format#bold,format#italic,links#modifylink,links#unlink,#paraformat]"/>
        </cui>
    </uiSettings>
</text>
```

### Full RTE configuration

A complete RTE wires up `rtePlugins` (what is enabled and how it behaves) and `uiSettings` (which
buttons appear, and in what order, for the inline, dialogFullScreen, and tableEditOptions toolbars).
This example enables formatting, lists, links, paragraph formats, a Styles dropdown backed by
component CSS, paste-as-plaintext, special characters, find/replace, and source editing.

```xml title="components/mycomponent/_cq_dialog/.content.xml - RTE field"
<text
    jcr:primaryType="nt:unstructured"
    sling:resourceType="cq/gui/components/authoring/dialog/richtext"
    fieldLabel="Body"
    name="./text"
    useFixedInlineToolbar="{Boolean}true">
    <rtePlugins jcr:primaryType="nt:unstructured">
        <format
            jcr:primaryType="nt:unstructured"
            features="[bold,italic,underline]"/>
        <subsuperscript
            jcr:primaryType="nt:unstructured"
            features="[subscript,superscript]"/>
        <lists
            jcr:primaryType="nt:unstructured"
            features="[ordered,unordered,indent,outdent]"/>
        <justify
            jcr:primaryType="nt:unstructured"
            features="*"/>
        <links
            jcr:primaryType="nt:unstructured"
            features="[modifylink,unlink]">
            <!-- Only allow internal and https links; protocols can be restricted -->
            <linkbrowserConfig
                jcr:primaryType="nt:unstructured"
                targetConfig="{Boolean}true">
                <targetConfig
                    jcr:primaryType="nt:unstructured"
                    mode="manual"/>
```

### Common RTE plugins

| Plugin (`rtePlugins/<name>`) | Notable features | Purpose |
|---|---|---|
| `format` | `bold`, `italic`, `underline` | Inline character formatting |
| `subsuperscript` | `subscript`, `superscript` | Sub/superscript |
| `lists` | `ordered`, `unordered`, `indent`, `outdent` | Lists and indentation |
| `justify` | `*` | Text alignment |
| `links` | `modifylink`, `unlink` | Anchor insertion; `linkbrowserConfig` controls the path picker and target |
| `paraformat` | block `formats` | Wrap selection in `p`, `h2`, `blockquote`, etc. |
| `styles` | CSS class dropdown | Apply semantic classes (preferred over inline styling) |
| `misctools` | `specialchars`, `sourceedit` | Special characters and raw HTML editing |
| `findreplace` / `undo` / `spellcheck` | `*` | Editor utilities |
| `edit` | `defaultPasteMode` | Controls paste behaviour (`plaintext`, `wordhtml`, `html`) |

### RTE tips

- **Keep the toolbar minimal.** Every button you add is a way for authors to produce off-brand
  markup. Start small and add on request.
- **Prefer the Styles plugin over inline formatting.** A `styles` dropdown that applies CSS classes
  keeps markup semantic and themeable; `format#bold` etc. bake presentation into the content.
- **Set `defaultPasteMode="plaintext"`** to stop Word/Google Docs styling from leaking into the JCR.
- **Limit `paraformat`** to the heading levels your design system actually uses, so authors cannot
  drop an `h1` into the middle of a page and break the document outline.
- **Render in the right HTL context.** Output RTE values with `@ context='html'` so AEM's XSS filter
  keeps the safe subset of markup - never `context='unsafe'`. See [HTL Templates](./htl-templates.mdx).
- For inline (in-context) RTE editing without opening the dialog, see
  [Inline editor](#inline-editor-edit-text-without-opening-the-dialog) below - it reuses the same
  `rtePlugins` structure.

## MSM / Live Copy considerations

Multi-Site Management (MSM) inherits a **blueprint** page into one or more **Live Copy** pages. By
default any content authored in the blueprint flows down to every Live Copy and overrides whatever
was there. `cq-msm-lockable` gives the Live Copy author per-field control: the field can be
*unlocked* to break inheritance on just that property, edited locally, and *re-locked* to resume
taking updates from the blueprint.

```xml
<ctaText
    jcr:primaryType="nt:unstructured"
    sling:resourceType="granite/ui/components/coral/foundation/form/textfield"
    fieldLabel="CTA Text"
    name="./ctaText"
    cq-msm-lockable="ctaText"/>
```

**How the attribute works:**

Adobe's [MSM lock rules](https://experienceleague.adobe.com/en/docs/experience-manager-65/content/implementing/developing/extending-aem/extending-msm) apply to the first child level of the resource being edited:

- A relative value, `ctaText` or `./ctaText`, adds that property name to the multi-value `cq:propertyInheritanceCancelled` on the component node. Both spellings address the same property. Core Components tend to write the `./` form.
- An absolute value, `/links`, cancels the child **node** `links`: MSM adds the `cq:LiveSyncCancelled` mixin on that child and sets `cq:isCancelledForChildren` to `true`.
- The chain icon is the Touch UI control. Re-enabling inheritance does not copy the blueprint value back. An author has to roll the page out again.

**Common pitfalls:**

- The value has to name the same property as `name`. A padlock with a different name still renders, and rollout keeps overwriting the field the author thinks is locked.
- `cq-msm-lockable` does not work for anything deeper than the first child. `./social/twitter` (a fieldset subnode) and `links/item0/label` (a multifield item) show the chain and are still overwritten. Lock the child node with an absolute value (`/links`, `/social`) if the whole group should break together.
- A per-market value that every Live Copy must change is a policy or a separate component, not a lock every local author has to open.

```xml title="Composite multifield locked as one child node"
<links
    jcr:primaryType="nt:unstructured"
    sling:resourceType="granite/ui/components/coral/foundation/form/multifield"
    composite="{Boolean}true"
    fieldLabel="Links"
    cq-msm-lockable="/links">
    <field
        jcr:primaryType="nt:unstructured"
        sling:resourceType="granite/ui/components/coral/foundation/container"
        name="./links">
        <items jcr:primaryType="nt:unstructured">
            <label
                jcr:primaryType="nt:unstructured"
                sling:resourceType="granite/ui/components/coral/foundation/form/textfield"
                fieldLabel="Label"
                name="./label"/>
            <url
                jcr:primaryType="nt:unstructured"
                sling:resourceType="granite/ui/components/coral/foundation/form/textfield"
                fieldLabel="URL"
                name="./url"/>
        </items>
    </field>
</links>
```

## Authoring UX tips

- Keep required fields early in the first tab.
- Use `fieldDescription` for guidance and examples.
- Prefer smaller, focused tabs over a single long list.
- Keep names stable; renaming properties impacts existing content.
- Use `granite:class` sparingly to improve spacing or emphasis.

## Accessibility

The Touch UI dialog (Coral) is keyboard- and screen-reader-accessible out of the box, but only if
you use the framework correctly. A few rules keep dialogs usable for everyone on the authoring team:

- **Always set `fieldLabel`.** The `field` Granite UI component wires the label to the input via
  `aria-labelledby` using a generated `labelId` ([Granite UI `field` contract](https://developer.adobe.com/experience-manager/reference-materials/6-5/granite-ui/api/jcr_root/libs/granite/ui/components/coral/foundation/form/field/index.html)).
  A field with no `fieldLabel` is unlabelled for screen readers.
- **Use `fieldDescription` for instructions**, not a separate `text` widget. The description is
  associated with the field (`aria-describedby`), so assistive tech reads it together with the label.
- **Don't rely on colour alone.** The invalid state adds the `is-invalid` class and an error tooltip
  with text - keep that text meaningful (see [Dialog Validation](./components/dialog-validation.mdx)).
- **Prefer Coral/Granite widgets over raw HTML** in the dialog. Hand-rolled markup in a `text` widget
  bypasses Coral's focus management and ARIA handling.
- **Keep a logical tab order.** Author tab order follows DOM order, so order your `items` the way you
  want the author to traverse them; avoid using CSS to visually reorder fields.
- **Label icon-only controls.** If you add custom buttons via clientlibs, give them an accessible
  name (`aria-label` or visible text).

See Adobe's [Coral UI](./ui/coral-ui.mdx) notes and the
[Granite UI server-side API](https://developer.adobe.com/experience-manager/reference-materials/6-5/granite-ui/api/jcr_root/libs/granite/ui/components/coral/foundation/server.html)
for the underlying accessibility contracts.

## AEM Component Help Pages

`helpPath` on the dialog root is where the Help (?) icon goes. An `https://` URL is enough. To show the component's own `README.md` inside the product, point `helpPath` at the components console detail view:

1. Open [CRXDE Lite](http://localhost:4502/crx/de/index.jsp) and the component, for example `/apps/<projectname>/components/some/text`.
2. Add a `README.md` under that component and write the author notes in it.
3. Open the [components console](http://localhost:4502/libs/wcm/core/content/sites/components.html) and select that component. It is listed only when it has a component group.
4. Copy the address bar. It looks like `/mnt/overlay/wcm/core/content/sites/components/details.html/apps/<projectname>/components/some/text`.
5. Set that path as `helpPath` on `cq:dialog`.
6. Drop the component on a page, open the dialog, and use the Help (?) icon.

### Set Documentation as Default Active Tab

The help view opens on the component properties. To make the documentation tab active, overlay the console node and order it first.

:::warning[Do not overlay `/libs` on AEM as a Cloud Service]
`helpPath` works on 6.5 and on Cloud Service. The overlay copies a `/libs` node into `/apps`, which Cloud Service does not allow. Use it on 6.5 on-prem only. See [AEMaaCS vs AEM 6.5](./infrastructure/aemaacs-vs-aem-65.mdx).
:::

1. In CRXDE Lite, open `/libs/wcm/core/content/sites/components/details/jcr:content/content/single/content/items/content/items/tabs/items/documentation`.
2. Overlay that node to `/apps` with **Match node types** checked.
3. On the overlay, set `sling:orderBefore` (String) to `fixedColumnContainer`.

`ui.apps/src/main/content/jcr_root/apps/wcm/core/content/sites/components/details/.content.xml`
